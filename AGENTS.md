## Visual direction

Make the design **eye-catching, polished, and personal**, with strong typography, thoughtful spacing, and a memorable hero section.

Use a deep navy or charcoal foundation, readable off-white text, and restrained teal or cyan accents. Choose harmonious colors and verify accessible contrast before finalizing them. Define reusable color, typography, spacing, and border-radius tokens so the design stays consistent.

Combine a bold introductory layout with attractive project cards and subtle visual details. Use abstract shapes or typography where personal photos or project screenshots are unavailable.

**Use SVG icons, never emojis.** Use one consistent icon library, such as Lucide. Pair icons with text when their meaning is unclear and give icon-only buttons accessible names.

Add subtle transitions and hover effects that improve feedback. Respect reduced-motion preferences. Avoid excessive animation, scroll hijacking, custom cursors, and effects that interfere with reading.

## UI/UX and accessibility requirements

Target **WCAG 2.2 Level AA**, and verify applicable requirements.

Include:

- Semantic HTML and a logical heading hierarchy
- Clear, consistent navigation
- Full keyboard access and visible focus indicators
- A skip-to-content link
- Accessible text and interface contrast
- Descriptive links and appropriate image alternatives
- Comfortable touch targets
- Accessible mobile navigation
- Layouts that support zoom and narrow screens
- Reduced-motion support
- Feedback that does not depend on color alone

Ensure sticky navigation does not cover section headings or keyboard focus. Use readable body text and comfortable line lengths.

## Technical requirements

Build reusable components and mobile-first layouts. Keep personal information, project content, and links in a centralized data file for easy editing.

Optimize assets, minimize dependencies, and add appropriate page titles, metadata, and a favicon. Verify mobile, tablet, and desktop layouts, keyboard navigation, links, and interactive states. Report any remaining accessibility or functionality limitations honestly.
